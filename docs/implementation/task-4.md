## 交付范围

- 新增会话状态和来源事件表及迁移 `0016_conversation_memory`。正式会话按应用、用户、客户端类型和未删除 Chat 授权；调试使用独立临时缓存。
- 事实新增、更正、待确认冲突、撤销、来源和版本记录；短事务统一锁记忆行，模型调用不持锁。重复轮次不重复提取，清除递增代次并保留无原话/值的轮次哈希标记，旧重答不能恢复已清除记忆。
- 有界提取使用现有 OpenAI 兼容 root_client，超时、输入/输出限制和禁用重试；严格校验引用、值、目标实体和明确更正意图。条件假设、问题和引用示例不自动确认为事实。明确编号列表支持“第二款”回查，其余含糊指代保留待确认。
- 回答选取完整事实与完整近期轮次；原始提取证据与任务 3 处理后的节点历史分开，保留 NODE 模式和去重结果。当前用户输入不截断。提取失败不注入未核对记忆。
- 撤销值仍不在有效快照中；从最近 100 个有变更事件生成只读 `revoked` 说明，参与相同预算。后续同键事实/待确认候选抑制旧撤销说明，清除后说明消失。
- 配置只允许一个顶层、无工具、无多模态的应用文本 AI 节点；拒绝循环内、其他工作流模式和同时引用旧 `memory` 模板。默认预算：回答历史 2048、提取输入 4096、提取输出 1024 token，超时 20 秒。
- 新增正式/调试 API，以及共享聊天面板的来源、纠正、确认、撤销、清除入口。版本冲突显示提示并保留更正草稿；UUID 使用现有 uuid 库，可在无 `crypto.randomUUID` 时操作。执行详情展示选择、变更和分项用量。

核心代码在 `apps/application/conversation_memory/`；聊天 API 在 `apps/chat/views/chat_memory.py`；面板在 `ui/src/components/ai-chat/component/conversation-memory/`。

## 真实模型对照

用户明确允许将人工编写的虚构测试对话发送到已配置百炼端点 `token-plan.cn-beijing.maas.aliyuncs.com`，使用 `qwen3.7-plus`，沿用 300 元共享预算保护。未发送生产聊天记录；未写入生产 Chat 或记忆表。对照使用真实 BaseChatNode 和真实供应商调用，调试状态使用 locmem；模型加载与无工具入口受控，不是完整 HTTP/工作流引擎验收。

固定配置：历史 3 轮、temperature=0、回答输出上限 1024、禁用 thinking；开启记忆额外执行一次提取。开发/首次验收的数据哈希提前封存，源码、模型修订、候选操作、实际消息、用量和耗时均留存。更改后同集复测明确标记为 regression，不冒充未见题的独立验收。

| 运行 | 最终回答观察（固定 / 记忆） | 总输入 token（固定 / 记忆） | 总输出 token（固定 / 记忆） | 累计节点耗时秒（固定 / 记忆） |
| --- | --- | --- | --- | --- |
| 开发集，2 题 15 轮 | 0/2 / 2/2 | 1524 / 14755 | 53 / 476 | 15.39 / 35.65 |
| 首次封存验收，3 题 23 轮 | 0/3 / 2/3 | 2644 / 23640 | 189 / 841 | 22.62 / 56.77 |

这些分数是 Codex 对最终回答的逐题核对，不是用户/独立人工评分；原始报告中的 `human_correctness=null`、`human_review=pending` 保持不变。样本很小，不能据此推断总体正确率。

首次封存验收中，记忆策略能答出相机预算 6500 元及法语/每天 20 分钟，但撤销题只询问是否要求防水：事实遗漏 1 次，未错误继承旧防水要求。原因是删除有效事实后没有保留撤销语义。补充只读撤销说明后，同集回归回答“不要求”，3 题均符合明确条件，观察到遗漏 0 次、错误继承 0 次。固定历史策略在两次运行中均对 3 个窗口外事实请求澄清，计为任务遗漏而非幻觉。

回归中记忆策略总输入约为固定策略的 9.03 倍，累计节点耗时约为 2.44 倍。该实现改善了本组长对话记忆，但**没有证明 token 或成本优化**。提取和回答实际 token 分开记录后汇总；价格/实际账单未知，费用保持 null。共享预算保守预留总额达到 58.172823 元（上限 300 元），该数值包含此前任务，且不是账单，不应当作本任务实际花费。

## 重现与使用

在配置好项目依赖及测试数据库权限的环境：

```bash
PYTHONPATH=apps python3 -m unittest discover -s tests/memory -v
python docs/implementation/scripts/run_task4_tests.py application
```

测试 runner 固定使用独立测试库并在其中安装 pgvector；不会迁移服务库。它使用 Django 的测试库创建/销毁流程，勿把同名测试库用作持久业务库。

评测脚本 `docs/implementation/scripts/run_task4_comparison.py` 需要 `--dataset-dir --split --output --budget-file --evaluation-module --baseline --code-sha`。output 必须不存在，验收 split 不允许截取题目。预算模块和模型配置沿用本机任务 1 环境，未将凭据打包进仓库。修改后的同集运行应使用新输出目录并明确标为回归。

集成时需先按常规部署流程执行新增迁移，再在支持的 AI 节点配置中主动启用“会话记忆”。停用只停止读取/更新，不删除既有记忆；删除使用面板“清除记忆”。清除不删除聊天记录及历史执行详情。

## 剩余验收与限制

- 待独立人工质量复核及新的未见题验收；同集修复回归不能补作原封存验收通过。
- 待完整登录/HTTP/工作流/浏览器端到端验收；第二款、冲突、清除主要由行为/数据库测试覆盖，本次真实模型小集未覆盖全部组合。
- 首版有界适配器仅支持现有 OpenAI 兼容 root_client。其他供应商显式 unsupported，保守退回当前输入和近期历史；未进行供应商通用上下文容量预检。
- 调试态受 1800 秒缓存生命周期限制。撤销说明回查最多 100 个有变更事件；更早内容可能被预算排除，不保证无限长期回忆。
- 现有 ChatRecord 整数汇总不能表示未知，有可能显示 0；应以节点 `memory.total_usage` 和分项为准。实账价格、费用未知。
- 未部署、未默认启用、未合并；任务 3 的人工/端到端限制继续保留。

可复用经验：将提取证据、回答历史和只读撤销说明明确分开；用真实交错事务而非串行测试验证并发。可在后续项目复盘中沉淀，未写入个人记忆。

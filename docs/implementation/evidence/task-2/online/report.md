## 可用功能

普通问答、工作流知识检索、重排后均调用统一在线适配器。应用/节点参数增加“已审核同义去重”，与原上下文去重和预算一起保存。详情显示审核命中、实际替代数、原始到保留来源映射、在线判断调用数，以及未配置/版本变化/无有效关系等状态。

策略只处理当前请求已获授权的输入证据。服务器审核注册表按工作空间隔离，绑定原文、标题、知识库、文档、段落、规范化元信息、规则和模型版本，并校验双向等价判断指纹。模型配置更新时间变化、原文变化、缓存损坏、缺失或超过24小时均保留原文，不在线调用判断模型、不自动续期；已有确定性去重和整段预算仍正常工作。

前端或聊天输入不能指定审核路径或审批内容。注册表默认位于 `/opt/maxkb/conf/semantic-context.json`，可由服务器环境变量 `MAXKB_SEMANTIC_REGISTRY` 配置。缓存仅由本机可信离线审核流程发布，不能把模型候选直接当作审批。

## 真实 HTTP 验证

通过 `127.0.0.1:8080/chat/api` 的认证、打开对话、问答接口，问同一问题“阅览室可以吸烟吗？”，每次新会话，关闭/开启各一次。最后重新发布为开启状态。

|项目|关闭|开启|
|---|---:|---:|
|送入模型的证据段数|2|1|
|应用记录输入 token|77|65|
|应用记录输出 token|7|6|
|合计|84|71|
|本次在线语义判断请求|0|0|

本次单题合计减少13 token，约15.5%。两次回答分别为“不可以，阅览室内禁止吸烟。”和“不可以，阅览室禁止吸烟。”，Codex 核对语义一致。开启记录包含 `semantic_duplicate`，映射指向知识库中真实保留段落；新增人工评分字段仍为空。该单题结果证明在线链路确实生效，不代表所有问题都能节省15.5%。证据见 `http-records.json`。

净 token 收益公式为“有效命中累计省下的输入和输出 − 首次及后续重新判断消耗”。当累计节省超过判断成本后可以净节省；不同问题节省量不同，不能把此前六组固定样例的约165次摊平值当成通用门槛。24小时过期后不再命中，重新审核成本也须计入。此次复制已批准样例没有新增付费判断，仅进行了两次有共享预算预留的真实回答和本地 embedding。

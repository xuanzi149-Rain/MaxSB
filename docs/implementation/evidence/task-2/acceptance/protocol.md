# 评测协议 v1

目的：为任务 2—6 建立可追溯、可解释的原版对照。所有资料为自行编写、可随项目发布的合成夹具，不代表真实机构政策；不从这些题的结果推断行业通用能力。

## 固定输入

`corpus.json` 中的逻辑 evidence_id 进入实际段落正文；导入后保存到真实 paragraph_id 的映射。`dev-v1.json` 有 20 题，`frozen-v1.json` 有 80 题。manifest 保存规范化 JSON 的 SHA256。题集封存前进行静态事实与规则审阅，此处的 Codex 编辑审阅不等于运行结果的人工评分。

多段证据题至少需要两个不同段落。长对话在关键条件与最终追问之间插入十轮无关信息；应用实际历史窗口记录在配置快照中。重复资料中的等价来源可用 required_evidence_groups 表达“任一来源足够”，避免把保留重复段落当成唯一正确行为。

工具题是独立的“受控工具工作流”分组：使用上游 start→tool 引擎执行版本化只读查件函数。它检测节点成功、错误与后续恢复能力，不证明 Agent 会自主选择工具或理解参数。相似运单用例是参数化重复测量，不算独立工具能力。超时通过真实工具函数抛出异常注入；观察到超时只代表注入成功，不代表用户任务完成。

## 评分与统计

- `fact_mentions` 仅为字面诊断；人工根据 expected_facts、acceptable_answers、rubric 复核语义及引用支持情况。
- 运行成功、规则检查通过与人工正确分开。未复核的最终正确率为未知；确认正确占全题集比例和复核覆盖率另列。
- 召回基于运行中真实检索证据，引用基于实际答案中的引用，二者不互相替代。
- 工具任务完成需要执行成功且满足预定义输出；超时失败保留为失败，不把期望超时误计为完成。
- 整个题集作为覆盖率分母，中断时未执行题仍在分母中。P95 仅统计已执行题并显示样本数，不能伪称完整批次 P95。
- 真实 token 仅采用供应商回调计量；上游 get_num_tokens 的估算另列。工作流线程未采集到用量时保持未知，不用零填补。
- 实际费用只接受可核对的供应商费用；当前无账单接入时为未知。每成功任务费用包含失败调用消耗；缺费用、混币、零成功或复核不完整均不报告该值。

## 运行与迭代

先用同一配置运行开发集两次，逐题记录答案/证据/评分差异；再运行一次冻结基线。冻结集不用于调参。知识库、应用、模型配置、代码与镜像均记录哈希/身份；已知环境不一致或批次不完整仅允许查看，不标为严格可比。模型服务商只提供漂移名称时明确记为“固定版本未知”。

人工复核保存真实登录用户、规则版本、时间与历史。第一轮报告按“证据未召回、条件丢失、错误继承、引用不支持、工具执行失败、基础设施异常”分析。以后每项优化同时检查质量、费用与耗时，不根据单次输出或少量重复题宣称显著提升。

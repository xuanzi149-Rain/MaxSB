# 任务 3 第二版：检索意图与多轮上下文改进

2026-10-10。实现已完成，新题对照观察到 token 下降，未新增必需证据召回回归。默认关闭，未修改已发布应用。此结论限于本轮 13 道新题，不能替代完整人工质量验收或证明通用意图识别能力。

## 改动及技能应用

- **RAG 与检索技术**：先检查完整会话控制意图，再判断问题复杂度。只有所有子句均为明确控制时才跳过；日常安排采用正向语法，不能因用户自称“无关”而跳过业务更正。混合意图、中文或阿拉伯数字约束、计算、额外请求子句和指代不确定时保守保留或扩大检索量。版本 2 决策与旧版重排接口兼容。
- **上下文工程与记忆管理**：AI 节点新增默认关闭的“轻量对话上下文”。提示模型使用用户最新明确更正；纯控制轮简短回应，业务答案不强制截断。显式选择资料来源后，只去除与当前资料完全一致、来源明确的历史资料副本，保留历史回答和用户原话。指代或来源不确定保留原文；工作流历史不改写。

配置位置：AI 节点的“轻量对话上下文”和“检索资料来源”；检索节点继续使用既有动态检索开关。工具及多模态节点不加轻量回答提示。执行详情可查看去除处数、字符数与简短回应状态。没有新依赖、数据库迁移或持久化记忆系统。

## 对照方法

新题 `acceptance-v2` 在真实模型运行前封存：13 题、25 个轮次，含多条件计算、混合意图、会话控制、重量更正、企业转个人身份、重复资料及模糊指代。题目和参考历史见 `inputs/`，哈希由 `verify-comparison.py` 检查。它与旧冻结集题目不同，但沿用同一语料且由同一作者编写，不是独立人工基准。

1. **相同历史**：两侧使用预先写好的相同用户消息和参考回答，关闭新增回答提示与历史去重，只测检索变化。逐轮验证除当前用户提示外，历史及系统消息逐字相同。
2. **自由对话 1**：固定流程与完整第二版各自生成历史，先固定后动态。
3. **自由对话 2**：同一题集、参数和规则重复，改为先动态后固定。

真实模型仍为已授权的 `qwen3.7-plus`，温度 0、最大输出 2048 token、无自动重试，使用原共享预算。三轮验收间未根据结果调整规则；相同历史轮之后仅修复了可选资料引用清空时的序列化兼容性，不改变检索或消息算法。源码归档均与快照逐文件哈希匹配。

## 结果

| 对照 | 完整配对题数 | 输入 token 固定→动态 | 输入变化 | 输出 token 固定→动态 | 输出变化 |
|---|---:|---:|---:|---:|---:|
| 相同历史，仅检索 | 13 | 6693 → 5406 | −19.23% | 1566 → 1457 | −6.96% |
| 自由对话，第 1 轮 | 13 | 15461 → 13485 | −12.78% | 2532 → 2046 | −19.19% |
| 自由对话，第 2 轮 | 12 | 15193 → 12648 | −16.75% | 2423 → 1846 | −23.81% |

第二轮 `v2-001` 动态侧发生 `APIConnectionError`，用量未知；比较同时排除了该题两侧，原始失败记录保留。不能把第二轮 12 题总量直接与第一轮 13 题总量比较，也没有把失败当零 token。

在新题的预标注意图中，第一版跳过 0/8 个无需资料轮次，第二版跳过 8/8；17 个需要检索的轮次均未误跳过。第二版仍有 14/25 轮保守回退，1 轮简单、2 轮复杂。这是本样本的覆盖结果，不是对任意自然语言的准确率承诺。

8 个控制轮的输出合计：第一轮 752 → 36 token，第二轮 561 → 31；动态侧每次最多 8 token。两轮各实际移除 1 处重复历史资料（272 字符）。因此本样本的主要收益来自跳过不必要检索及避免控制轮展开回答，历史资料去重只贡献了较小部分；没有用字符数冒充 token。

三轮均无新增必需证据召回回归，知识库前后哈希一致。`v2-002`“领取包裹需要出示哪些信息”两侧都没有召回 `F-code`，回答均不完整，问题仍保留。不得宣称全部检索质量问题解决。

Codex 对照实际回答检查了重点场景：自由对话两轮的 `v2-011` 均根据最新 7 千克条件判定不能使用限重 5 千克的自助柜；`v2-012` 均保留个人身份、不支持月结；计算与多约束题 `v2-004` 保留所需证据。模糊指代题 `v2-010` 仍可能列举多个假设和不必要说明，第一轮动态答案还有“通常视为通用操作规则”这样的推断，不能当作完整质量通过。正式人工正确率与引用准确率评分仍待完成。

## 验证与成本

- 123 项测试通过：63 项原上下文、23 项检索/对话纯测试、37 项 application 集成测试。新增测试覆盖混合意图、中文数量、额外请求子句、礼貌前缀指代、历史来源、保留更正、关闭策略、工具提示隔离和清空可选引用。
- Vue 类型检查、管理端构建、AI 节点局部 ESLint 通过。全量 ESLint 仍为基线 103 错误、1 警告；AI Python 文件有 4 处旧 `E721`，HEAD 对照一致，新增模块及修改入口 Ruff 通过。
- 独立只读审阅发现的边界问题均经失败测试复现后修复。验收集运行后未用其失败题调规则。
- 含两次开发集运行，本轮 174 次受预算保护的请求尝试，173 次有成功模型记录，1 次连接失败。保守预留从 42.146568 元增至 49.656357 元，新增 **7.509789 元**，低于原累计 300 元上限。实际账单未知，未据 token 下降宣称实账节省。

## 证据与适用边界

`comparison.json`、`intent-comparison.json` 和 `budget-check.json` 给出核对指标；`shared/`、`free-1/`、`free-2/` 保存全部逐轮消息、答案、计量、错误与节点轨迹。`dev-real/` 与 `dev-continuity/` 保留开发过程，包括初始更正条件被模型忽略的失败，未混入验收数字。

运行 `python3 verify-comparison.py` 可离线复核题集、语料、源码哈希、共享历史一致性、逐轮计量、成功配对排除和预算请求数。环境与命令见 `reproduction.txt`。

仍未覆盖真实重排模型、完整工作流引擎/HTTP 端到端以及大样本人工质量验收。规则是有限且保守的；简短提示不构成硬输出长度上限。历史轮数保持原配置（实测为 3），更早的事实仍可能掉出窗口，需由任务 4 的结构化记忆处理。当前适合继续受控验证，默认关闭，不自动发布启用。

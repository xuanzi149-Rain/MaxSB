## 源码依据与方案选择

- `apps/application/flow/step_node/mcp_node/impl/base_mcp_node.py` 解析工具和参数，校验引用工具授权，调用 `SandboxMCPBackend.call_tool`，目前直接把返回的文本内容作为结果；新路径必须检查 MCP 的 `isError`，不能把业务错误当成功。
- `apps/application/flow/backend/sandbox_mcp.py` 通过独立 session 调用远端工具，可在该调用边界实施异步超时；超时或取消只代表本地停止等待，不证明远端取消了写入。
- `apps/application/flow/workflow_manage.py` 的 `load_node` 从 ChatRecord 详情调用各节点 `save_context`，已有恢复上下文的能力，但不能直接视为具备持久检查点、并发互斥或版本安全。
- `tool_node` 的 Python 执行路径依赖 ToolExecutor 的进程超时和通用异常；首版不同时改这条路径。

可选方案：只加节点重试改动最少，但不能完成失败处恢复；重建通用 DAG/循环持久执行器覆盖最广，但超出单项增量范围。推荐在现有工作流调度器增加受限恢复路径，首版选择 MCP 节点，并复用经过测试确认可完整重建的节点上下文。

## 首版边界

仅支持正式应用聊天中的顶层串行、无分支无循环工作流；允许开始节点、MCP 工具节点及无工具的文本 AI 节点。启用恢复时，不支持的节点、分支、子工作流、表单暂停、多模态和异常分支由服务端在调用任何工具前拒绝；导入、发布和运行均校验。AI 节点只在回答完全结束且检查点保存后视为已完成，部分流式输出不是完成证据。

只从失败 MCP 节点继续；首版不承诺 AI 节点失败后的恢复，不给调试运行提供持久恢复入口。用户取消不自动恢复。无策略的旧流程继续走原路径，不能被新范围限制影响。

运行级恢复开关与 MCP 节点重试配置随工作流版本保存。节点参数：每次尝试超时默认 10 秒（1–120），最多重试默认 2 次（0–5，首次调用不计入重试），可重试错误白名单和工具副作用模式。有限退避为 0.5、1、2、4、8 秒，轨迹记录实际等待。人工恢复次数上限默认 3，防止无限继续。

## 工具契约与重试规则

副作用模式默认 `unknown`，配置可明确为 `read_only`、`idempotent_write` 或 `unprotected_write`。MCP 注解只是提示，不作为写入安全证明；受控工具必须实测其契约。

只读工具允许重试超时和明确可分类的暂时性传输错误。参数、认证、权限、工具不存在及明确业务失败直接终止；未识别异常不重试。不能以错误文案含某个关键词推断可重试；实现通过异常类型和结构化状态分类，包装异常也须保守处理。MCP `isError` 默认是业务失败，不自动重试。

幂等写入要求工具提供显式幂等参数及工具侧原子去重；服务端校验该参数可传入，覆盖为系统生成值，用户不能覆盖。幂等键绑定原始 run UUID 和固定节点执行标识，在自动重试、人工恢复和进程恢复中不变；新运行生成新键。配置声明不等于安全保证，只有经过响应丢失等测试的工具才在报告中标为安全恢复。

未知或无保护写入在请求发出后发生超时、断连、进程消失时标 `outcome_unknown`，停止自动重试及普通恢复。人工确认入口允许记录“已执行”或“未执行”及证据：已执行须提供符合工具输出契约的可核对结果；未执行仅在确认原调用已终止且无副作用后允许继续。无法核对保持未知。该操作限定应用管理权限，记录操作者、理由和时间，不让聊天用户通过一个布尔值绕过保护。

## 持久化与调度

新增运行、步骤和尝试记录，复用 Chat/Application 所有权关系。运行保存 chat/record、原始运行 UUID、发布版本及规范化工作流指纹、引用工具定义指纹、状态、恢复次数和认领版本。步骤保存顺序、节点标识、状态、解析后的业务输入快照、输出、恢复所需变量、幂等键。尝试保存起止 UTC 时间、耗时、错误分类和脱敏结果摘要。所有记录保持关联，清理聊天时同步清理。

步骤状态：pending → running → succeeded / failed / outcome_unknown。每次远端调用前先持久化尝试意图；成功输出和步骤完成在同一事务落库后才调度下一节点。数据库写入失败不得继续后续步骤。输入在首次执行时冻结，恢复不重新求值历史模板，不重新调用已成功 AI 节点；无法序列化或超过明确容量限制时在首次远端调用前拒绝。

工具凭据、连接认证头和环境密钥不进入普通快照或轨迹，恢复时重新从授权配置解析。业务输入可能含敏感值：数据库快照仅经归属校验访问，普通轨迹只展示允许字段；禁止持久化任意执行对象或 pickle。引用工具定义、影响行为的初始化配置改变也视为版本变化。

恢复先验证身份、会话状态、运行归属、当前发布版本、工作流和工具定义指纹，再通过短事务和条件更新原子认领。外部调用不持有数据库锁；同一请求 UUID 重放返回已有恢复结果，不启动第二个执行器，另一并发请求返回 409。恢复请求不得覆盖输入、节点或幂等键。

工作进程使用有期限认领和心跳，提交检查点校验认领代次。认领过期不证明旧远端请求停止：只读工具可重试，幂等工具沿用原键，无保护写入转未知。过期旧执行器不得提交新检查点或推进下游。幂等工具去重保留时长必须覆盖允许恢复窗口，过期后拒绝自动恢复。

恢复只载入成功步骤的持久输出和变量，从失败节点开始；不盲目重放全部 ChatRecord.details。原运行与恢复尝试共享逻辑运行 ID，各次恢复另有请求 ID 和来源记录。UI 展示已持久化输出，SSE 恢复事件携带节点/尝试标识，客户端不能把历史输出再次追加成重复答案。

## API、权限与界面

拟新增聊天端运行详情和恢复接口：`GET /chat/api/tool_runs/{run_id}`、`POST /chat/api/tool_runs/{run_id}/resume`。恢复请求含 request_id、expected_version；不接收任意输入快照。沿用 ChatTokenAuth，同时限定 application_id、chat_user_id、chat_user_type 和有效 Chat；跨会话、不存在及无权限统一不可访问。恢复前重新校验当前工具授权，分享详情不获得恢复权。

未知结果确认使用管理端接口及现有应用管理权限，不开放普通聊天写入。API key 沿用现有应用身份边界，不宣称能区分共用 key 的最终用户。

工作流配置增加恢复开关，MCP 节点增加超时、重试及副作用契约配置。执行详情显示步骤状态、每次尝试、错误类型、恢复来源和不能恢复的原因；失败且可恢复时出现继续入口。版本变化提示新建运行，但不能自动创建新运行以绕过未知写入风险。

## 验证与验收

先写失败行为测试再实现。独立测试数据库验证迁移、并发和事务；受控 MCP 服务记录调用数、稳定键和实际写入次数，注入成功、超时、暂时性失败、明确业务失败及写入成功后响应丢失。

- 重试上限、错误白名单、参数与权限错误不调用/不重试，超时和 MCP isError 分开统计。
- 连续两个工具中第二个失败，HTTP 恢复后第一个调用数保持 1；缓存清空或进程重启后仍成立。
- 工作流/工具定义变化拒绝，撤销工具权限拒绝，输入不能被恢复请求替换；旧配置关闭时行为不变。
- 并发重复恢复、请求重放、认领过期、旧进程迟到结果和检查点写入失败。
- 幂等写入响应丢失后沿用原键，远端实际写入 1 次；无保护写入保持未知且不自动重试；确认审计及权限隔离。
- 完整节点模型输入、变量和输出恢复验证；不只测试重试辅助函数。流式与非流式均覆盖，已完成 AI 节点不重复计费调用。
- UI 真实接口联调；相关任务 2/3 回归、改动 Python 检查、只读 ESLint、Vue 类型检查及两种构建。保留已有基线失败，不全仓自动修复。

故障报告按场景列运行数、完成率、重复副作用次数、失败至恢复完成耗时及恢复请求至完成耗时、额外调用/token/费用。明确业务失败和未知结果保留在分母中并单独解释。纯工具测试无模型调用才可填额外 token=0；外部工具费用或模型用量不明时标未知。重复副作用必须为 0 且确实执行响应丢失与并发测试，才可对受测工具宣称安全恢复；不推广为任意工具 exactly-once 保证。

# 任务 1–5 验收与部署闭环计划

日期：2026-10-10。目标是在保留现有数据和证据的前提下，使默认分支、GitHub 与本机隔离部署反映已验收的实际能力；未取得证据的项目保留未验收标记。

重点技能：Agent 评测与效果迭代（复核题集、逐题结果和失败）；生产级系统能力（迁移、版本、回退、真实 HTTP 与运行源码核验）。

1. 在独立集成分支恢复任务 1 的评测源码、题集、报告及测试；将其迁移接在任务 5 的 `0017_tool_recovery` 后，合并当前路由、模型注册和前端入口。核对任务 2/3 的运行源码已在主线，不能以旧分支全量覆盖后续任务。
2. 在集成树上运行评测核心、Django/API、任务 2–5 相关回归，检查迁移图、前端类型与双端构建。记录既有失败与新增失败，修复新增问题。
3. 用当前部署数据的只读核查确认任务 2、3、5 的未完验收项。能通过现有测试环境完成的 HTTP/浏览器联调补做；需要真实人工逐题签收、账单或外部服务保证的项目，保留明确待办，不把代理判断写作人工结论。
4. 对本机 8084 隔离实例制作可回退源码和数据库备份，应用新迁移，在默认关闭功能的状态下做真实 API、页面和重启探针；运行版本与 Git SHA、资源哈希一致后更新部署记录。
5. 更新任务总览和逐项状态，提交、合入并推送默认分支；再核对 GitHub SHA、干净工作树和服务运行版本。任何验证失败均停止发布并保留旧实例。

完成条件：任务 1 代码与数据可从 GitHub 默认分支复现；任务 0–5 每项均有准确的实现、验收、测试部署状态；8084 运行版本与发布记录一致。完整验收只能在原计划每项条件实际满足后标记。

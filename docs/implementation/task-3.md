# 任务 3：动态检索预算

2026-10-10，用户确认实施有界增量方案。范围是现有工作流知识检索节点及显式关联的重排节点；普通问答管线没有新增此开关。

## 技能应用与验收

- **RAG 与检索**：在 embedding / 向量查询之前确定是否检索及候选上限，通过明确规则决定是否重排。新增能力是按问题分配检索资源，并保留原始候选与真实段落来源。证据是节点行为测试、执行详情和封存题集的分组召回对照。
- **Agent 评测与效果迭代**：按无需资料、单事实、比较/多条件、未知分别比较固定与动态策略；复杂题缺失必需证据明确列为失败。未知用量、费用、正确率与引用准确率不当作零，规则命中不当作回答正确。

## 配置和执行

检索节点参数保存于 `knowledge_setting.retrieval_policy`，默认关闭。旧工作流无需迁移。

```json
{
  "enabled": true,
  "none": {"retrieve": false, "top_n": 1, "rerank": false},
  "simple": {"retrieve": true, "top_n": 3, "rerank": false},
  "complex": {"retrieve": true, "top_n": 8, "rerank": true}
}
```

每类候选上限允许 1–10000。关闭检索时实际候选数为 0，且不重排。相似度阈值和检索模式沿用原有配置。默认数字是初版配置，不是冻结题集调参结论。

首版只有完整寒暄匹配才进入无需资料类；混合提问仍检索。比较词、多个事实问句或多问号进入复杂类。明确且较短的单事实问句进入简单类。空问题、明显指代追问及无法明确识别的输入沿用原检索参数，重排也沿用其固定配置。规则不调用额外模型，不读取对话以推断不确定指代。

动态开启后，检索节点提供：

- `retrieval_budget`：规则版本、题型、原因、最终参数、状态、原始命中数、检索耗时。
- `retrieved_paragraph_list`：授权检索后、上下文处理前的原始候选。
- 原有 `paragraph_list` / `data`：保持任务 2 上下文处理语义，可直接供模型使用。

需要动态重排时，在重排节点的“动态检索预算关联”中选择检索节点的预算决策；唯一重排输入必须是同节点的原始检索候选，问题也必须一致。在重排节点设置最终上下文去重与预算，模型引用重排节点的 `result`。这条分支的数据顺序是原始检索候选 → 重排或跳过 → 去重和预算 → 最终文本；检索节点自身处理后的文本是另一可引用输出，不作为该重排分支的输入。

不关联时，现有重排行为保持不变。关联但上游动态策略关闭时，使用原有处理后的段落，继续固定重排。动态要求重排但模型缺失或调用失败时保留原始排序，记录 `unavailable`，继续上下文处理；未知问题和未关联重排仍保留原异常语义。轨迹不包含模型供应商的原始异常载荷。

执行详情显示决策、实际输出、原始候选和任务 2 来源映射。界面不会把候选数或估计 token 宣称为实际费用。

## 验证与限制

证据与实际运行结果见 [task-3/report.md](evidence/task-3/report.md)。复现脚本为 `scripts/run_task3_comparison.py`，按任务 1 的 manifest 校验题集和语料哈希，输出目录必须不存在，避免覆盖旧记录。

真实模型模式要求既有共享预算文件，沿用任务 1 的预算预留与请求上限。此前外部模型调用被自动审批拒绝；用户随后明确回复“授权执行”，本轮已获准沿用原共享 300 元累计预算运行。真实评测已完成：输入 token 增加 3.83%，输出 token 增加 18.21%，且保留新增证据回归，质量验收未通过。详见 [真实模型报告](evidence/task-3/real-model-report.md)。

`--retrieval-only` 是安全替代验证：只访问本机数据库与 embedding，阻断 requests/httpx 外部 HTTP，不调用回答模型。其真实召回和耗时可核对；回答正确率、模型输入 token、引用准确率和实际费用仍未知。工具题标记不适用，不能作为检索优化收益。历史任务 1 导出缺少完整提示配置，因此当前成对检索对照不冒充历史原版严格对照。

关闭策略即可恢复原有检索配置；清空重排预算关联即可恢复独立重排行为。没有数据库迁移或新增依赖。本轮不会改变既有应用的已发布配置。


## 第二版：检索意图与轻量对话上下文

用户确认实施后，重点应用 RAG 与检索、上下文工程两项技能。此次仍是现有节点增量，不新增持久化会话记忆。

检索规则版本为 2。会话控制按完整子句识别，只有所有子句均为明确控制指令才跳过检索；明确的日常安排使用正向语法，不接受任意自称“无关”的业务更正。混合问题、指代、数值/中文数量、计算与不能确定为单事实的附加子句保守保留或扩大检索量。重排节点兼容版本 1 和 2。

AI 节点新增 `dialogue_policy_enabled`（默认 false）及 `dialogue_context_reference`（可选的上游文本引用）。界面显示为“轻量对话上下文”和“检索资料来源”。开启后，提示模型以用户最新明确更正为准；纯寒暄或会话控制只简短回应，业务问题不强制截断。工具及多模态调用不加此提示。

节点历史只有在保存了资料来源、旧资料与当前资料完全一致、当前提示确实含有该资料、旧提示中的资料唯一且不会移除用户原话时，才去掉旧资料副本。历史回答和用户原话均保留，显式指代追问保留原历史；工作流级历史保持原样。执行详情记录移除处数、字符数与简短回应状态，字符数不等于 token。

本策略不增加历史轮数，不替代任务 4 的结构化记忆；超过原历史窗口的事实仍可能丢失。未识别的自然语言安排继续检索，不能把规则覆盖宣称为通用意图理解。

评测增加 `--history-mode shared`：两侧使用预先封存的相同用户原话与参考回答，只比较检索变化；`--history-mode free --dialogue-policy` 比较固定流程与完整第二版；`--strategy-order dynamic-first` 可反转运行顺序。新题和参考回答在模型运行前封存，验收结果不用于本轮调参。结果见 [第二版报告](evidence/task-3/revision-2/report.md)。

## 新增能力与范围

开始节点显式开启 `tool_recovery` 后，正式应用支持单条串行的开始节点、MCP节点与无内置工具的文本AI节点。默认关闭，旧工作流路径保持原有语义。分支、循环、多模态、调试、re_chat、任意节点跳转在该模式下拒绝。

MCP节点配置单次超时（1–120秒）、重试次数（0–5）、副作用类型和幂等契约。仅显式白名单的超时/暂时性错误可重试；业务错误、鉴权/参数错误不重试。写入需要工具侧字符串幂等参数及保留期，原运行和恢复沿用同一键及冻结输入。未知/无保护写入在结果不确定时停止，管理员须记录远端核对证据；确认已执行则使用确认输出，确认未执行才允许重新派发。取消本地等待不代表远端回滚。

持久化 ToolRun/ToolStep/ToolAttempt，包含租约、执行代次、请求去重、版本指纹、输出/变量检查点与每次尝试。恢复跳过成功工具/AI，不再次生成其答案。支持租约过期、节点之间退出以及最后检查点成功后未保存最终记录的恢复；旧代次不能覆盖最终答案。恢复前校验会话归属、逻辑删除、当前版本、引用工具定义/授权及新聊天分支。普通恢复最多3次、24小时窗口，并受工具幂等保留期限制。

新增聊天运行查询/继续 API、管理结果确认 API、开始/MCP节点配置、步骤轨迹和恢复面板。响应只向聊天身份返回公开答案与白名单状态；内部系统提示词和记忆详情不通过公开恢复接口返回。恢复结果按原 record_id 合并，避免追加重复回答。

## 故障报告

[封存报告](evidence/task-5/fault-report/report.json)记录功能提交与恢复模块源码SHA256。6个受控场景中4个完成（66.7%），业务拒绝和未知写入均留在分母；重复副作用0。自动重试场景平均端到端耗时0.522秒；人工恢复请求至检查点完成0.011秒（不包含人工核对等待，也不是生产延迟）。两者口径不同，不合并比较。

报告只调用受控工具，没有外部模型调用，模型调用/token均为0；费用未知保留null，不能据此宣称真实供应商成本下降。版本变化、并发、崩溃和AI跳过由独立行为测试覆盖，不伪装成这6个计时样本。真实网络MCP的写入计数见Transport测试，而非用调用次数推算写入次数。

## 配置与首版边界

增加 `model_routing` 配置，默认关闭，随工作流版本保存。开启时显式选择两个不同的 LLM 配置 ID，分别维护模型参数；“低成本/高能力”是管理员指定角色，不由模型名称猜测。原有模型选择在关闭时继续生效，开启时界面明确显示两模型配置取代本节点原模型选择。

首版支持应用工作流顶层纯文本 AI 节点，包括综合上游 MCP/工具节点已产生的文本结果。启用路由的节点不能绑定工具、MCP、子应用或技能，不能使用图像/视频输入，也暂不与该节点的结构化记忆同时启用；循环及非应用工作流不在首版支持范围。保存、发布和运行均验证这些组合，在任何模型调用前返回明确错误。其余节点关闭路由时不受新限制。

验证两个模型的工作空间、类型、可用状态和既有授权规则；禁止直接接收供应商 URL 或密钥。检查资源依赖收集、导入/导出及复制是否识别新增的两个模型引用，避免发布后丢失依赖。

## 可解释决策与输出契约

分类输入使用原始用户问题和配置的任务契约；不让待处理文档正文中的关键词自行决定路由。明确的单一抽取或分类请求且配置了结构化输出契约才走低成本路径。多证据比较、多条件、工具结果综合、历史指代依赖、混合意图或无法识别一律走高能力模型。复杂规则优先于简单规则，轨迹记录规则版本、规则 ID、原因和所选模型。

首版契约为 JSON 对象及必需顶层字段，可选引用字段。引用白名单只从显式绑定、实际送入当前提示词的检索证据提取，绑定不成立则拒绝配置/运行；不由模型自报合法引用集合。严格解析 JSON，检查字段及引用类型，拒绝未知引用 ID。对开放文本不做模型自评升级。

低成本答案发生 JSON 解析失败、必需字段缺失或非法引用时，以同一份冻结消息和输出契约调用高能力模型一次；失败草稿不加入后续提示词。模型超时/传输失败也最多升级一次，并单独记录执行失败原因；认证、权限或无效配置直接失败，不用升级掩盖配置错误。高能力返回也执行相同契约校验，不合格或调用失败则节点失败。没有第三次重试。

## 流式输出、状态与计量

需要契约校验的调用在服务端缓冲，完整通过后才按现有 SSE 协议输出最终答案；低成本失败片段和推理内容不输出给用户或下游。缓冲设置明确大小上限和调用超时，取消则停止继续升级。此模式会增加首字等待时间，界面说明并由评测记录。无输出契约且直接高能力的开放回答可沿用实时流式输出，输出后发生错误不得再次升级或伪装成功。

同一节点执行使用稳定任务标识，各次调用另有 attempt ID。详情包含角色、实际模型 ID/名称、开始/结束时间、耗时、状态、校验错误码、升级原因及用量来源；不保存密钥、认证头和原始异常对象。无论成功或失败，都保存已经发生的调用轨迹。

用量优先采用供应商返回的实际 input/output/cache 等计量，估算值单列。任意一次计量缺失时相应总量为未知，同时保留已知分项。分别记录两模型的价格版本、币种、计费模式和适用时段；只有用量与价格规则完整时计算按价格核算费用，实际账单金额单列，不能把预算预留当作实际费用。混合币种不直接相加，未知费用不计作零。

扩展评测回调按调用 ID 去重并绑定模型，避免节点计量与回调计量重复相加；响应失败但已产生费用的尝试仍保留。核查聊天汇总和异常详情，防止上游 token 估算覆盖路由的实际/未知计量。任务 5 恢复检查点保留最终模型结果与完整路由轨迹，恢复已完成 AI 节点时不再次调用。

## 界面、评测与验收

节点配置提供开关、两模型选择、独立参数和输出契约；执行详情展示选模原因、升级条件和逐次用量。复用现有评测页面按题型展示三组运行：固定低成本模型、始终高能力模型、路由策略。各组使用相同题集、消息、输出契约和校验口径，失败均保留在分母。

建议在冻结评测前锁定以下质量门槛：路由整体正确率不低于始终高能力组，各题型正确率亦不下降，必需证据和引用不出现新增回归；并且每成功任务的完整合计费用下降，才报告“成本优化”。报告同时列升级率、用量/费用覆盖率和 P95，不声称有限样本能保证所有生产请求。人工评分按既有规则保留复核人；缺少复核或完整费用时只报告功能结果。

实际两个模型及版本、可核查价格来源和本轮付费预算在真实调用前确定，写入实验配置并扩展预算白名单；不沿用单模型预算去覆盖未授权的新模型。不修改或提前读取冻结题答案来调整规则；开发仅用开发集。

先写失败行为测试，再实现：简单/复杂/未知/混合意图；JSON/字段/引用校验；升级成功、双失败和取消；流式片段不泄漏；双次费用求和与缺失用量；越权、禁用模型和非法组合；旧节点关闭兼容；真实节点消息一致、任务 5 恢复不重放。运行相关任务 1–5 回归、改动 Python 静态检查、只读前端 lint、类型检查和管理/聊天构建。将执行命令、退出码和未通过项落到任务 6 证据目录。
